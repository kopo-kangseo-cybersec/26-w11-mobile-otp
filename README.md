# 모바일 OTP — TOTP 2단계 인증 (`26-w11-mobile-otp`)

> 이 README는 실습을 완성한 뒤, 배포 직전 단계에서 직접 채워 넣습니다.
> 실습 안내와 완성 기준은 [`guide.md`](./guide.md)를 참고하세요.

## 소개

웹 서비스(인증 서버)와 스마트폰 Authenticator 앱의 동작을 한 화면에서 동시에 비교·검증할 수 있는 **양방향 모바일 OTP(TOTP) 실시간 동기화 스튜디오**입니다.

- **좌측 패널 (웹 서비스 역할)**: 서비스명(발급자)과 계정을 입력해 안전한 Base32 비밀 키를 발급하고, `otpauth://totp/...` 형식의 QR 코드를 표시해 스마트폰 앱과 연동하며 사용자가 입력한 6자리 코드를 검증합니다.
- **우측 패널 (가상 Authenticator 모니터)**: 30초 카운트다운 프로그레스 바와 함께 브라우저가 직접 계산한 6자리 예상 OTP 번호를 실시간으로 표시하여 스마트폰 앱의 번호와 일치하는지 즉시 확인할 수 있습니다.

## 나의 AI 기획·구현 과정

1. **선택한 AI 협업 방식**: **Gemini(웹)에서 먼저 기획 및 아키텍처 설계 → Antigravity IDE에서 코드 구현 및 디버깅** 방식을 선택했습니다. 웹 Gemini와 대화하며 RFC 6238 표준 로직과 양방향 비교 UI 구조를 먼저 정리한 뒤, Antigravity IDE에서 파일을 구성하고 테스트했습니다.
2. **화면과 기능 구상**: 사용자가 처음 접속했을 때 별도 설정 없이도 즉시 비밀 키와 QR 코드가 발급되어 스마트폰으로 스캔할 수 있도록 구성했습니다. 또한, 스마트폰 번호를 직접 타이핑해 검증하는 흐름과 화면 우측의 예상 OTP 번호를 원클릭으로 입력창에 채워 테스트할 수 있는 편의 흐름을 함께 설계했습니다.
3. **구현 중 막혔던 문제와 해결 과정**:
   - **파일 경로 및 모듈 연결 오류**: Vite 프로젝트 환경에서 루트 폴더와 `src` 폴더 경로가 어긋나 `main.js`와 CSS가 로드되지 않는 404 오류가 발생했으나, 개발자 도구(`Console`) 로그를 통해 경로(`/main.js`, `./totp.js`)를 정확히 매칭하여 해결했습니다.
   - **QR 코드 캔버스 렌더링 문제**: 초기 외부 QR 라이브러리의 브라우저 전역 객체 인식 문제로 QR 영역이 빈 화면으로 표시되었으나, `qrcode-generator` 라이브러리로 교체하고 HTML5 `<canvas>`에 직접 QR 픽셀을 렌더링하도록 수정해 해결했습니다.

## TOTP 원리 및 보안 점검 (사이버보안과 체크포인트)

1. **`Math.random()` 대신 `crypto.getRandomValues()`를 사용해야 하는 이유**:
   `Math.random()`은 의사난수 생성기(PRNG)로 내부 시드(Seed) 상태를 기반으로 동작하므로 출력 패턴을 예측할 수 있는 보안 취약점이 있습니다. 반면 `window.crypto.getRandomValues()`는 운영체제 수준의 암호학적으로 안전한 난수 생성기(CSPRNG)를 사용하여 공격자가 비밀 키를 추측하거나 역산하는 것을 방지합니다.
2. **외부 서버 대신 브라우저(`crypto.subtle`)에서 직접 연산할 때의 보안상 이점 (Zero-Transmission)**:
   비밀 키 생성과 64-bit Big-Endian 카운터 기반 HMAC-SHA1 연산을 외부 백엔드 API로 전송하지 않고 브라우저 내장 Web Crypto API(`crypto.subtle`)로만 처리하면, 네트워크 구간에서의 중간자 공격(MITM)이나 서버 로그 유출로 인한 비밀 키 탈취 위험을 원천 차단할 수 있습니다.
   - **Network 탭 점검 결과**: 개발자 도구(`F12`) → `Network` 탭을 열어둔 상태에서 비밀 키 발급, QR 생성, 30초 코드 갱신 및 검증을 수행한 결과 외부 서버로 전송되는 API 요청이 **0건**임을 확인했습니다.
3. **스마트폰 Authenticator 앱과의 실시간 번호 일치 여부**:
   스마트폰의 Google Authenticator 앱으로 화면의 QR 코드를 스캔해 등록한 결과, PC 화면 우측에 표시되는 6자리 OTP 번호와 스마트폰 앱의 6자리 번호가 매 30초 주기로 정확히 일치하고 동시에 갱신됨을 확인했습니다.

## 나만의 확장 기능

- **시간 오차 허용(Time-Step Window) 토글**: 실제 인증 서버 환경과 유사하게 네트워크 지연이나 기기 간 미세한 시계 오차를 보정할 수 있도록 현재 스텝(`0`)뿐만 아니라 앞뒤 30초(`±1` 스텝) 범위까지 검증을 허용하는 체크박스 옵션을 구현했습니다.
- **임박 알림 시각 피드백 & 원클릭 테스트**: 코드 만료 5초 전부터 타이머 바와 숫자가 붉은색으로 전환되어 갱신 임박 상태를 직관적으로 알려주며, 빠른 기능 테스트를 위한 비밀 키 복사 및 예상 코드 자동 채우기 버튼을 추가했습니다.
