# 모바일 OTP — TOTP 2단계 인증 (`26-w11-mobile-otp`)

> RFC 6238 (TOTP) 표준 알고리즘과 브라우저 내장 Web Crypto API를 활용하여, 네트워크 통신 없이(Zero-Transmission) 30초마다 6자리 일회용 비밀번호를 생성하고 검증하는 **모바일 OTP 체험 스튜디오 웹앱**입니다.

---

## 📱 프로젝트 소개

이 웹앱은 사이버보안 전공 학생의 시각에서 **"인터넷 연결이 전혀 없는 오프라인 상태에서도 스마트폰과 서버가 어떻게 30초마다 똑같은 6자리 번호를 공유할 수 있는가?"**라는 질문을 한눈에 이해하고 실습할 수 있도록 제작된 **2분할 인터랙티브 체험 스튜디오**입니다.

### 🌟 화면 구성 및 주요 기능
- **왼쪽 [서비스 설정 & 로그인 검증기 (Service Provider Role)]**:
  - 발급자(Issuer, 기본값: `KopoCyberSec`) 및 계정명(`student@kopo.ac.kr`) 실시간 메타데이터 커스텀
  - `새 비밀키 발급` 버튼: `crypto.getRandomValues()`를 사용한 160-bit Base32 비밀키 발급 및 원클릭 복사
  - 클라이언트 사이드 인메모리 QR 코드 렌더링 (`qrcode.react` 기반 `otpauth://totp/...` URI)
  - 6자리 인증번호 입력창 및 즉각적인 성공/실패 시각 피드백 배지
  - 기기 간 미세 시간 오차를 감안한 **$\pm 1$ 스텝(앞뒤 30초) 시간 오차 허용 토글** 지원
- **오른쪽 [내장 모바일 웹 인증기 (Virtual Authenticator Client Role)]**:
  - 실제 스마트폰 Authenticator 앱을 모사한 디바이스 프레임 (노치, 상태바, 오프라인 모드 강조, 배터리)
  - 가독성을 극대화한 실시간 6자리 OTP 표시 (3자리씩 공백 분리: `123 456`)
  - 30초 카운트다운 타이머 및 실시간 프로그레스 바 (유효시간 5초 미만 시 붉은색 경고 애니메이션)
  - 원클릭 **"이 번호를 검증기 입력칸에 채우기"** 자동 입력 인터랙션 지원
- **하단 [사이버보안 원리 가이드 & Zero-Transmission 검증]**:
  - RFC 6238 3대 요소(비밀키, 타임스탬프 카운터, HMAC-SHA1 동적 절단) 및 무전송 원칙 교육용 카드 제공

## 🤖 나의 AI 기획·구현 과정

### 1. AI 협업 방식: Antigravity IDE 기반 대화형 Implementation Plan (`/plan`)
- **기획 단계**: 무료 웹 Gemini에서 무작정 코드를 복사하지 않고, Antigravity IDE 내부에서 `/plan` 슬래시 커맨드를 호출하여 **구현 명세서(Implementation Plan)**를 먼저 수립했습니다.
- **아키텍처 검토**: RFC 6238/RFC 4226/RFC 4648 표준 규격을 별도 유틸리티 모듈(`src/utils/totp.js`)로 완벽히 분리하고, 좌우 2분할 레이아웃과 Zero-Transmission 원칙을 아티팩트를 통해 사전 검토 및 승인한 뒤 단계별로 개발을 진행했습니다.

### 2. 구상 및 화면 설계
- 사용자가 접속하자마자 직관적으로 비교할 수 있도록 좌측은 서버(인증 관리자), 우측은 스마트폰(사용자)으로 역할을 분리했습니다.
- 스마트폰 카메라로 QR 코드를 스캔하는 즉시, 화면 우측의 모바일 목업에 표시되는 6자리 번호와 내 실제 스마트폰(Google Authenticator) 화면의 번호가 1초의 오차도 없이 일치하도록 설계했습니다.

### 3. 디버깅 및 트러블슈팅 경험
- **트러블슈팅 1: JSX 수식 텍스트 파싱 오류 (`Time is not defined`)**
  - **문제**: 사이버보안 가이드 컴포넌트(`SecurityNotice.jsx`) 내 설명 문구 중 `(\text{Time})` 수식의 중괄호 `{Time}`을 JSX 컴파일러가 자바스크립트 변수로 해석하여 렌더링 시 `ReferenceError`가 발생하고 화면이 멈추는 현상이 발생했습니다.
  - **해결**: 미리 선제적으로 도입해 둔 `ErrorBoundary.jsx`가 오류 화면과 원인 메시지를 정확히 출력해 주어 빠르게 원인을 파악할 수 있었습니다. 수식 텍스트를 JSX 안전 표준 텍스트 및 `<code>` 태그로 리팩토링하여 완벽히 해결했습니다.
- **트러블슈팅 2: RFC 6238 표준 테스트 벡터 검증**
  - **문제**: 스마트폰 앱마다 번호가 다르게 뜰 위험을 사전에 차단하기 위해 알고리즘 정밀 검증이 필요했습니다.
  - **해결**: RFC 6238 공식 표준 부록의 SHA-1 테스트 벡터(시크릿: `GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ`)를 기준으로 노드 환경에서 $T=59\text{s}$, $1111111109\text{s}$, $1111111111\text{s}$, $1234567890\text{s}$, $2000000000\text{s}$의 예상 값(`287082`, `081804`, `050471`, `005924`, `279037`)과 정확히 일치하는지 단위 검증을 통과시켰습니다.

## 🛡️ TOTP 원리 및 보안 점검 (사이버보안과 체크포인트)

### 1. `Math.random()` 대신 `crypto.getRandomValues()`를 사용해야 하는 이유
- **`Math.random()`의 취약점**: 일반 `Math.random()`은 유사난수 생성기(PRNG)로, 내부 알고리즘(예: V8의 xoroshiro128+)과 시드(Seed) 값이 시간에 기반하므로 공격자가 이전 생성 난수 몇 개를 관찰하면 향후 생성될 난수와 비밀키를 수학적으로 완벽히 예측(Reverse Engineering)할 수 있습니다.
- **`crypto.getRandomValues()` (CSPRNG)**: 운영체제(OS) 커널의 엔트로피 풀(하드웨어 잡음, 마우스 인터럽트, CPU 타이밍 등)을 기반으로 동작하는 암호학적 난수 생성기입니다. 다음 난수를 예측하거나 역산하는 것이 수학적으로 불가능하여 비밀키 생성에 필수적입니다.

### 2. 브라우저 로컬 연산(Web Crypto API)과 Zero-Transmission 원칙의 보안상 이점
- **무전송 원칙(Zero-Transmission)**: 비밀키 생성, HMAC-SHA1 연산, QR 코드 렌더링이 외부 백엔드 서버나 제3자 API(예: Google Charts API)로 전송되지 않고 브라우저 샌드박스 내부(`window.crypto.subtle`)에서만 완결됩니다.
- **보안상 이점**:
  1. 비밀키가 네트워크 구간(Man-in-the-Middle) 도청 위험에 전혀 노출되지 않습니다.
  2. 서버 침해 사고나 외부 API 서비스 장애가 발생해도 OTP 기능에 영향을 주지 않습니다.
- **개발자 도구 검증 결과**:
  - 브라우저 개발자 도구(`F12`) → **Network** 탭을 활성화한 상태에서 '새 비밀키 발급', 'QR 코드 갱신', 'OTP 계산'을 반복 수행해도 **외부로 나가는 HTTP/WebSocket 통신 패킷이 0건(Zero Request)**임을 직접 확인했습니다.

### 3. 실제 스마트폰 Authenticator 앱과의 일치 검증
- 스마트폰의 **Google Authenticator** 및 **2FAS** 앱으로 웹 화면의 QR 코드를 스캔하여 계정을 등록했습니다.
- 스마트폰 화면에 뜨는 6자리 숫자와 PC 웹 브라우저 우측 [내장 모바일 웹 인증기]의 6자리 숫자가 **매 30초 정각마다 100% 동일하게 일치하며 동기화**되는 것을 확인했습니다.
- 스마트폰에 표시된 번호를 웹의 [인증 검증기]에 입력했을 때 **"인증 성공 (SUCCESS)"** 판정을 받았습니다.

## 🚀 나만의 확장 기능

1. **시간 오차 허용 윈도우 ($\pm 1$ 스텝) 토글 기능**:
   - 모바일 기기와 PC 간의 시계가 1~2초 어긋나 30초 경계에서 인증이 실패하는 현실적인 클록 드리프트(Clock Drift) 문제를 해결하기 위해, 현재 스텝($T_0$) 외에 직전($T_{-1}$)과 직후($T_{+1}$)를 검증할 수 있는 보안 옵션을 제공합니다.
2. **모바일 Authenticator 목업 프레임 UI**:
   - 단순한 텍스트 출력을 넘어 스마트폰 상단 노치, 오프라인(NO-NET) 상태 표시, 배터리, 3자리 단위 공백 분리 폰트(`123 456`) 등 실제 모바일 디바이스 감성을 충실히 구현했습니다.
3. **원클릭 자동 채우기 인터랙션**:
   - 모바일 인증기에 뜬 6자리 코드를 클릭 한 번으로 왼쪽 서비스 검증기 입력창에 자동으로 전송·입력해 주는 편의 버튼을 탑재했습니다.
4. **React ErrorBoundary 런타임 방어 체계**:
   - 예기치 못한 스크립트 오류 발생 시 흰 화면 크래시를 방지하고 사용자가 즉시 인지하고 새로고침할 수 있는 에러 뷰를 제공합니다.
